Viikko 48: Unity auki, asiakkaan kysymykset ja issuet

Repository ja GDD on jo tehty. Tee ensin ohjaajan kanssa ensimmäinen onnistuminen. Jatka sitten työvaiheesta 48-1 ja liitä Unity-projekti olemassa olevaan repositoryyn työvaiheessa 48-2. Tee asiakastehtävät ohjaajan kanssa.

Työvaihe 48-1

Luo Unity-projekti ja kokeile selaimessa

  1. Avaa Unity Hub → Installs. Tarkista ohjaajan sopima Unity 6 -versio. Sen valikosta Add modules tarkista Web Build Support. Jos asennus vaatii ylläpitäjän oikeudet, pyydä ohjaaja avuksi.
  2. Avaa Projects → New project. Valitse Universal 2D. Kirjoita Project name: CafeGame. Kuvan versio on 6000.5.8f1; käytä oppilaitoksen sopimaa Unity 6 -versiota ja omaa kansiotasi.
  3. Jos repositoryssa ei vielä ole Assets-kansiota (siinä on esimerkiksi README, .gitignore ja project-docs), luo Unity-projekti erilliseen väliaikaiseen kansioon. Liität sen repositoryyn työvaiheessa 48-2. Jos repositoryssa on jo Unity-projekti, avaa se Hubissa Add project from disk -toiminnolla ja jätä uuden projektin luonti väliin.
  4. Paina Create project ja odota editorin avautumista. Avaa Project-ikkunasta Assets. Luo tarvittaessa Scenes-kansio: hiiren oikea → Create → Folder.
  5. Valitse File → Save As. Tallenna scene nimellä CafeGame kansioon Assets/Scenes. Project-ikkunassa näkyy CafeGame-scene. Paina Play ja sitten uudelleen Play: palaat muokkaustilaan.
  6. Avaa File → Build Profiles. Unity 6:n alaversiosta riippuen valitse Web → Switch Platform tai Add Build Profile → Web → Add Build Profile → Switch Profile. Jos Web puuttuu, palaa moduulien tarkistukseen.
  7. Avaa Scene List. Lisää nykyinen scene Add Open Scenes -painikkeella; joissakin versioissa valitse ensin Override Global Scene List. Jätä mukaan vain Assets/Scenes/CafeGame. Poista SampleScene-rivin rasti, jos se on listassa.
  1. Valitse Build And Run. Luo kohdekansio Builds/Test Unity-projektin sisään. Älä käytä docs-kansiota. Odota selaimen avautumista; tyhjä tausta on tässä oikea tulos.
  2. Ota kuva selaimesta Windowsin kuvakaappaustyökalulla. Tallenna kuva työpöydälle nimellä web-test.png. Siirrät sen repositoryyn työvaiheessa 48-2. Kirjaa Unity-version koko numero päiväkirjaan.

Pysähdy ja tarkista: Unity-projektissa on CafeGame-scene, ja Build And Run avaa testiversion selaimeen.

Jos ei onnistu: Älä avaa buildin index.html-tiedostoa kaksoisklikkaamalla. Käytä Build And Run -toimintoa. Jos tulee virhe, avaa Window → General → Console ja näytä ensimmäinen punainen viesti ohjaajalle.

Työvaihe 48-2 · osa 1/2

Liitä Unity-projekti olemassa olevaan repositoryyn

  1. Avaa GitHub Desktop ja valitse oma repository. Valitse Repository → Show in Explorer. Jätä tämä kansio auki.
  2. Jos omaa repositorya ei vielä ole koneella, käytä pääohjeen GitHub Desktop -kuvaohjetta. Jo perustettua repositorya ei luoda uudelleen.
  3. Sulje Unity. Avaa työvaiheessa 48-1 luomasi Unity-projektin kansio toisessa tiedostoikkunassa.
  4. Kopioi Assets, Packages ja ProjectSettings repositoryn juureen. Säilytä alkuperäinen kopio, kunnes olet saanut projektin auki uudesta kansiosta. Älä kopioi Library-, Temp- tai Builds-kansioita. Älä korvaa repositoryn README- tai .gitignore-tiedostoa.
  5. Tarkista repositoryn .gitignore: siinä pitää olla Unity-pohjan säännöt Librarylle ja Tempille sekä Buildsille. Jos ne puuttuvat, pyydä ohjaajaa lisäämään Unity-pohja ennen commitia.
  6. Avaa Hub → Projects → Add → Add project from disk. Valitse repositoryn juurikansio, jossa Assets, Packages ja ProjectSettings ovat. Avaa projekti ja kaksoisklikkaa Assets/Scenes/CafeGame.

Pysähdy ja tarkista: Unity avautuu repositoryn kansiosta ja CafeGame-scene näkyy.

Jos ei onnistu: Jos Hub ilmoittaa, ettei kansio ole Unity-projekti, tarkista sisäkkäiset kansiot. Assets-kansion täytyy olla suoraan valitsemassasi kansiossa.

Työvaihe 48-2 · osa 2/2

Tallenna työ GitHubiin

  1. Luo repositoryn juureen kansio project-docs/evidence/week-48. Siirrä työpöydältä kuva web-test.png tähän kansioon.
  2. Täydennä README.md: pelin työnimi ja yhdellä virkkeellä pelin tarkoitus. Älä poista aiempaa hyödyllistä sisältöä.
  3. Avaa GitHub Desktop → Changes. Tarkista kansiokartan mukaan, mitä muutoksia tallennetaan. Jos Library tai Temp näkyy, pysähdy ja korjaa .gitignore ohjaajan kanssa.
  4. Kirjoita Summary-kenttään ”Lisää Unity-projektin pohja”. Paina Commit to main ja sitten Push origin. Jos painikkeessa lukee Publish branch, julkaise olemassa olevan repositoryn haara.
  5. Valitse Repository → View on GitHub. Tarkista, että tiedostot ja commit näkyvät. Kopioi commitin linkki viikon 48 päiväkirjan kenttään Missä työnäyte on? Päiväkirjan viet Gitiin viikon lopussa.

Pysähdy ja tarkista: GitHubissa näkyvät Unity-projekti ja selainkuva. Osaat näyttää repositoryn ja oman commitin.

Jos ei onnistu: Jos Changes on tyhjä, varmista, että Unity-projekti on juuri tämän repositoryn kansiossa. Push on valmis vasta, kun commit näkyy verkkosivulla.

Työvaihe 48-3 · osa 1/2

Lue toimeksianto ja valmistele kysymykset

  1. Avaa pääohjeen Toimeksianto. Kirjoita paperille kaksi otsikkoa: Vaaditaan ja Avoin asia.
  2. Kirjoita Vaaditaan-kohtaan pelin pakolliset asiat. Ota ensimmäiseksi esimerkiksi aloitusvalikko.
  3. Kirjoita Avoin asia -kohtaan toimeksiannon neljä asiakkaalta kysyttävää asiaa: testiselaimet ja laitteet, kohderyhmä ja kierroksen pituus, top 5 -tasatilanteet sekä hyväksyjä.
  4. Muotoile näistä neljä kysymystä. Lisää yksi oma kysymys toimeksiannosta. Käy lista ohjaajan kanssa läpi.
  5. Kirjoita jokaisen kysymyksen alle, mitä vastaus ratkaisee. Esimerkki: ”Kuinka pitkä kierros on?” → ”Ajastimen aloitusarvo”. Tallenna viisi kysymystä viikon 48 päiväkirjaan.

Pysähdy ja tarkista: Viisi erilaista kysymystä ja viisi päätöstä löytyvät päiväkirjasta.

Jos ei onnistu: Jos et keksi omaa kysymystä, näytä ohjaajalle toimeksiannosta kohta, jota et ymmärrä. Muotoilkaa siitä kysymys yhdessä.

Työvaihe 48-3 · osa 2/2

Keskustele asiakkaan kanssa

  1. Sovi ohjaajan kanssa keskustelun aika ja asiakkaan edustaja. Ohjaaja voi toimia toimeksiannon mukaisena asiakkaan sijaisena.
  2. Käy lista läpi ja kysy yksi kysymys kerrallaan. Kirjaa vastauksen sisältö heti kysymyksen alle.
  3. Jos vastausta ei saada, kirjoita ”avoin”. Sovi, kuka selvittää sen seuraavaksi.
  4. Käy pakollisten ominaisuuksien lista asiakkaan kanssa läpi. Kirjaa päivä ja osallistujien roolit viikon 48 päiväkirjaan.
  5. Avaa tiedosto project-docs/gdd.md VS Codessa. Kirjoita asiakkaan vastaukset kohtaan, jossa ovat asiakkaan kanssa sovittavat asiat. Avoimiin kohtiin kirjoitat sanan avoin. Tallenna, tee commit ja push.

Pysähdy ja tarkista: Jokaisella kysymyksellä on vastaus tai merkintä avoin. Pakolliset ominaisuudet on käyty läpi.

Jos ei onnistu: Ohjaaja auttaa järjestämään keskustelun. Asiakasvastauksia ei täytetä esimerkkivastauksilla.

Työvaihe 48-4 · osa 1/2

Tee pieniä GitHub-tehtäviä

  1. Aloita ensimmäisestä featuresta: pelattava kierros (viikko 49). Feature-lista on Suunnitelma (GDD) -näkymän kohdassa Featuret tekojärjestyksessä. Kirjoita paperille: rakenna ruudut, kytke Aloita, valitse kahvi, toimita ja näytä pisteet, testaa selaimessa. Nämä ovat rajattujen tehtävien esimerkkejä.
  2. Avaa oma repository selaimessa → Issues → New issue. Jos näkyy mallivalinta, valitse tyhjä issue. Kirjoita ensimmäinen otsikko: ”Vaihda valikosta peliruutuun”.
  3. Kirjoita kuvaus neljällä otsikolla: Miksi tarvitaan, Teen, Valmis kun, Arvio. Kuva näyttää yhden mallin. Kirjoita oma arvio; sovi ohjaajan kanssa enintään päivän tehtävistä.
  4. Paina Create tai Submit new issue. Avaa tehtävä uudelleen ja tarkista, että kuvaus tallentui.
  5. Tee ensimmäisestä featuresta 3–5 rajattua tehtävää.
  6. Lisää pääohjeen mukaisesti myöhemmistä featureista yksi tehtävä kustakin. Asiakkaan muutostoivetta ei vielä arvata. Näytä lista ohjaajalle.

Pysähdy ja tarkista: Ensimmäisen featuren tehtävät on pilkottu; myöhemmät featuret näkyvät listassa. Jokaisessa on arvio ja testattava Valmis kun -ehto.

Jos ei onnistu: Aloita yhdestä mallitehtävästä yhdessä ohjaajan kanssa. Tee seuraava itse ja tarkistuta se ennen koko listan kirjoittamista.

Työvaihe 48-4 · osa 2/2

Merkitse tehtävien tärkeys ja hyväksytä rajaus

  1. Avaa Issues → Labels → New label. Luo P0 pakollinen, P1 tärkeä ja P2 lisä. Jos tunnisteet ovat jo olemassa, käytä niitä.
  2. Avaa yksi issue. Valitse sen Labels-kohdasta sopiva tunniste. Toimeksiannon vaatimusten toteutukset ovat P0 pakollisia.
  3. Tunnista yhdessä ohjaajan kanssa mahdolliset lisäideat: esimerkiksi ylimääräinen animaatio voi olla P2, jos toimeksianto ei vaadi sitä. Älä muuta pakollista ominaisuutta valinnaiseksi.
  4. Jos listassa on vain vaatimusten toteutuksia, kaikki voivat olla P0. Lisätehtäviä ei tarvitse keksiä vain tunnisteiden käyttämiseksi. Osaa kuitenkin selittää, milloin P1 tai P2 olisi sopiva.
  5. Näytä tehtävälista ja GDD ohjaajalle. Kirjaa hyväksyjän rooli, päivä, hyväksytty rajaus ja mahdolliset korjaukset päiväkirjaan.

Pysähdy ja tarkista: Jokaisella tehtävällä on tärkeysluokka. Ohjaaja on hyväksynyt rajauksen. Osaat erottaa pakollisen ominaisuuden lisäideasta.

Jos ei onnistu: Kysy jokaisen epäselvän tehtävän kohdalla: voiko asiakkaan toimeksiannon mukaisen pelin luovuttaa ilman tätä?
